# Тиждень 2 — що робить кожен, крок за кроком

Все вже написано. Ваша робота — запускати в правильному порядку і копіювати числа. Нічого вирішувати не треба.

**Порядок:** учасниця 1 (перший запуск) → учасниця 3 (аналіз і зміни моделі) → учасники 2 і 4 (дашборд, Genie, презентація).
Учасники 2 і 4 можуть починати свої кроки 1–3 одразу, паралельно.

---

## 0. Один раз перед стартом (хто-небудь, 5 хвилин)

1. Перенесіть у репозиторій нові файли: `notebooks/06_city_c_diagnose.py`, `notebooks/07_city_c_model_change.py`,
   `jobs/job3_new_city.yml`, папку `docs/`. Commit & Push. Кожен робить **Pull** у своєму Git folder.
2. Власниця моделі (учасниця 3) відкриває Catalog → `workspace` → `airbnb` → Models → `price_model` →
   **Permissions** → **Grant** → обирає учасницю 1 → привілей **EXECUTE** → Grant.
   Без цього перший запуск впаде на правах, а не на даних.

---

## Учасниця 1 — перший запуск на Нашвіллі

1. Jobs & Pipelines → Create → Job → (⋮) **Edit as YAML** → вставити `jobs/job3_new_city.yml`.
   Замінити `<REPO>` на шлях свого Git folder, `<JOB_1_ID>` на id Job 1 (видно в URL Job 1). Save.
2. **Run now** без змін параметрів (city=nashville, model_alias=week1, run_label=c_first_run).
3. **Нічого не виправляти під час запуску.** Коли завершиться:
   - якщо все зелене — зробити скріншот сторінки запуску;
   - якщо щось червоне — відкрити червону задачу, скопіювати текст помилки, зробити скріншот.
4. Написати в README розділ «City C report → First run»: що впало (або «все відпрацювало»), повідомлення помилки.
5. Якщо щось впало — скинути помилку в чат з Claude, отримати виправлення, внести його, **записати рядок у
   таблицю змін у README з позначкою «pipeline fix»**, і перезапустити Job 3. Повторювати, доки скоринг не пройде.
6. Написати учасниці 3: «Перший запуск готовий».

---

## Учасниця 3 — аналіз і зміни моделі

1. Відкрити `notebooks/06_city_c_diagnose`, Serverless, **Run all**. Віджети за замовчуванням правильні.
2. Внизу ноутбука з'явиться **Draft report**. Скопіювати його повністю в README, розділ «City C report».
   Скріншоти таблиць «three numbers» і розбивки помилок — учасниці 4 для слайдів.
3. Відкрити `notebooks/07_city_c_model_change`, **Run all**. Займає кілька хвилин.
4. Внизу з'явиться таблиця змін з числами. Скопіювати її в README, у таблицю змін («model change»).
5. Commit & Push.
6. Надіслати учасниці 4: draft report з кроку 2 і таблицю з кроку 4.

Якщо будь-який ноутбук впав — скриншот помилки в чат з Claude.

---

## Учасник 2 — дашборд

1. Sidebar → Dashboards → Create dashboard.
2. Вкладка **Data** → для кожного запиту з `docs/dashboard_queries.sql` → «Create from SQL» → вставити → назвати як
   у коментарі `-- dataset: ...`.
3. Зробити три сторінки, як підписано у файлі (City overview, Cross-city, Model). Тип графіка підписаний біля кожного
   запиту.
4. Правила оформлення: бари від нуля, сортування за значенням, одне місто кольором, решта сірим, без пирогів.
5. **Заголовок кожної сторінки — висновок, а не назва.** Шаблони є у файлі; підставити числа з графіків.
6. Після того як учасниця 3 запустила ноутбук 07 — оновити дашборд (Refresh): Нашвілл з'явиться на сторінці Model.
7. Publish → скопіювати посилання → учасниці 4.

---

## Учасниця 4 — Genie і презентація

1. Genie: зробити все за `docs/genie_setup.md` (таблиці, інструкції, приклади SQL).
2. Поставити Genie три питання із завдання і перевірити відповіді проти SQL у файлі. Якщо помиляється — дописати
   речення в інструкції. Робити скріншоти «було / стало»: це слайд «трюки для Genie».
3. Коли прийдуть числа від учасниці 3 — попросити Claude зібрати презентацію (надіслати draft report, таблицю змін і
   числа тижня 1). Структура вже узгоджена: висновок першим слайдом, історія Нашвілла в центрі, деталі в додатку.
4. Сценарій демо: хто що показує (1 — пайплайн і перший запуск, 2 — дашборд, 3 — модель, 4 — Genie).
   Зробити запасні скріншоти на випадок, якщо демо не завантажиться.
5. PDF презентації — в репозиторій, посилання в README.
